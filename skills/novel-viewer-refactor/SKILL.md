# ノベルビューア リファクタリングスキル

`hitohira.html`、`docs/SPECIFICATION.md`、`AGENTS.md`を同時に扱うリファクタリングで使用する。機能追加そのものではなく、既存機能を維持しながら構造・用語・仕様の不整合を整理することを目的とする。

## 基本手順

1. `AGENTS.md`と技術仕様書を先に読み、用語・保存・エクスポート・入力操作の不変条件を抽出する。
2. 実装を検索し、同一概念を表す識別子、イベント処理、保存処理、判定処理の重複を一覧化する。
3. 正規の状態と共通関数を一つ決め、重複経路を統合する。互換性維持だけの古い識別子や廃止済み処理は残さない。
4. 挙動を変えない範囲で関数の責務を分離し、処理順序・非同期処理・エクスポート復元経路を明確にする。
5. 用語変更はコード、UI、仕様書、テスト、スキル内の参照を同じ変更で更新する。
6. 仕様書にはユーザーが観測できる動作だけを残し、実装上の一時的な回避策や変更履歴を記載しない。開発方針は`AGENTS.md`に置く。

## このプロジェクト固有の整理基準

- `本文パネル`、`文章`などの正規用語を使い、表記揺れを残さない。
- 設定・本文・読書位置・IndexedDBメディアの保存責務を混在させない。読書位置は設定初期化判定から除外する。
- エクスポートHTMLは埋め込みデータを唯一の復元経路とし、元ページのBlob URLや外部実行時データへ依存させない。
- Markdown変換とHTMLサニタイズを分離し、リンクは安全なスキームだけを許可する。
- テキスト選択、キーボード連続スクロール、モーダル中の背景操作、Wake Lock、初期化ボタンの状態更新をイベント重複なく維持する。
- UIアイコンはインラインSVG・`currentColor`・最小限のピクトグラムに統一し、操作ラベルとアイコンを混同しない。

## 検証

- `node tests/novel_viewer_unit_test.js`を実行する。
- 単体テストを追加・拡充した場合は、変更後のテストを必ず実行し、全件成功を確認する。
- テストは描画、保存、エクスポート、入力操作、UIの責務単位へ分割できる構成を保ち、修正の影響範囲に応じて実行単位を決める。共通状態・仕様書・`AGENTS.md`・HTML構造の変更は全件実行とする。
- `git diff --check`を実行する。
- 変更した用語・識別子を`rg`で検索し、旧名称や重複処理が残っていないことを確認する。
- 仕様書と`AGENTS.md`の相互参照が正しく、コード内の保存キー・IndexedDB名・ショートカット表記と一致することを確認する。
- 動作を変更した場合は、変更前後で保持すべき不変条件を単体テストへ追加してから完了とする。

大規模な構造変更では、まず小さな単位で編集・テストし、各段階で差分と実行結果を確認する。リファクタリングを理由に仕様変更や互換性拡張を暗黙に追加しない。
