# 開発計画

現在の未解決課題は[課題表](./ISSUES.md)を正とし、優先度順に対応する。[宣言的要求](./REQUIREMENTS.md)を実装する際は本書で実施順を計画する。製品動作は[仕様書](./SPECIFICATION.md)、テスト範囲は[カバレッジマトリクス](./coverage_matrix.md)、再利用可能な確認結果は[開発知見](./DEVELOPMENT_KNOWLEDGE.md)で管理する。

## 宣言的要求から計画を作る

宣言的要求に基づく作業では、要求をそのまま作業項目に写すのではなく、現状との差分と、利用者から観測できる完了条件へ分解する。

1. 要求資料、関連する製品仕様、実装、テスト、課題を確認し、要求ごとに現状・不足・依存関係を整理する。
2. 実施項目ごとに要求ID、順序、成果、依存関係、検証方法、状態を記録する。要求に明記された優先度があればそれに従い、なければ依存関係と利用者への影響・データ損失・安全性・再現性を基準に順序を決める。
3. 作業を妨げる未解決事項は[課題表](./ISSUES.md)へ登録する。仕様競合や期待結果が複数に分かれる曖昧さは、競合点・影響・解消案をユーザーへ示し、回答を待つ間も独立して進められる項目を実行する。
4. 完了条件の検証結果を計画に反映し、未達項目は阻害要因・再開条件・次の作業とともに課題表で追跡する。要求本文の変更はユーザーが直接行うか、明示的に指示した場合に限る。

## 更新ルール

- 実施順序と状態は課題表に合わせる。阻害された課題を飛ばす場合は、課題表に事実・阻害要因・再開条件を記録する。
- 課題が完了したら課題表から削除し、利用者向け仕様・テスト・カバレッジを必要に応じて更新する。
- 公開版を変更したらビルドし直し、[テスト実行ガイド](./TESTING.md)のオフライン配布検証を実行する。
- 新しい再利用可能な知見は[開発知見](./DEVELOPMENT_KNOWLEDGE.md)へ記録する。一時的な進捗や未解決事項は記録せず、課題表または本計画で管理する。
