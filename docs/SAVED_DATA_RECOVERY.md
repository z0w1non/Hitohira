# 保存処理の復旧エラーへの対応

保存処理の復旧エラーが表示された場合、ビューアーは不整合な保存状態を読み込まず、復旧マーカーと保存データを保持して起動を止める。初回の再試行で一時的なIndexedDB読み取り失敗から回復する場合がある。

## 利用者が最初に行うこと

1. このタブを閉じる。
2. 同じブラウザー・同じプロファイルでビューアーをもう一度開く。
3. エラーが続く場合は、ブラウザーのサイトデータやプロファイルを削除・初期化せず、そのまま保持する。

サイトデータの消去は、ブラウザーにだけ保存された本文、読書位置、元ファイル、復旧記録を失わせる可能性がある。通常のビューアー画面からは、この状態の復旧記録を編集・削除できない。

## 開発者・サポート担当者が調査する場合

復旧に失敗したオリジンとブラウザープロファイルを特定し、作業前にプロファイル全体のバックアップを作成する。対象オリジンのLocalStorageとIndexedDBを読み取り専用で退避し、次のキーと値を記録する。

- LocalStorage：`hitohira_pending_saved_data_transaction`、`hitohira_content`、`hitohira_settings`、文書別の`hitohira_position:*`と`hitohira_bookmarks:*`
- IndexedDB：`hitohira_media_db`の`background_media`ストアにある`current`、`current_text`、`__pending_transaction__`

復旧内容の妥当性とバックアップを確認する前に、保存値・復旧記録・ブラウザープロファイルを削除しない。保存領域を変更する修復は、バックアップの複製環境で検証してから行う。

## 検証済み範囲

- 単体テストで破損JSON、未知形式、不正なLocalStorageキー・IndexedDB操作、適用失敗、孤立記録、対応記録の欠落を確認する。
- Chromeブラウザー操作テストで、破損マーカーとIndexedDB記録欠落時に起動を止め、本文を読み込まず、LocalStorageのマーカーを保持することを確認する。
- ブラウザー実プロファイルでプロセス中断の各タイミングを強制した試験や、プロファイル破損の自動修復は保証しない。
