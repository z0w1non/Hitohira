# Hitohira 仕様書

- 対象ファイル：`hitohira.html`
- 形式：CSS・JavaScriptを内包する単体HTML
- 本書は実装仕様を説明する文書であり、対象ファイルの実装との整合性を保証しない。

## 製品概要

ブラウザー上で小説本文を読むための単体型ビューア。本文の書字方向・書体・文字組み・配色を調整できる。本文や背景メディアの読み込み、目次、読書進捗表示、読書位置の保存、HTMLエクスポート、読み込んだ元ファイルの個別エクスポートに対応する。

外部サーバーや外部ライブラリを前提とせず、ブラウザー標準APIで動作する。製品HTMLとエクスポートHTMLは、起動・閲覧・読み込み・保存・エクスポートの実行時にネットワーク接続を要求しない。開発時の生成ツールは外部ライブラリを利用できるが、利用者の実行時依存として残さない。ファイルの保存・復元はブラウザーのストレージ機能と実行環境に依存する。

製品HTMLとエクスポートHTMLは、起動・閲覧・読み込み・保存・エクスポートの実行時にネットワーク接続を要求しない。開発時の生成ツールは外部ライブラリを利用できるが、生成HTMLへ必要なコードとデータを埋め込み、実行時依存を残さない。

GitHubリポジトリのトップページに表示するルート`README.md`から、`public/hitohira.html`を直接ダウンロードできる。ルートの開発用`hitohira.html`とは内部パスで区別し、リンクは生成済み公開HTMLを指す。利用者はダウンロードしたファイルを開いてすぐ使用できる。

## 用語定義

| 用語 | 定義 |
|---|---|
| ビューア | 本アプリケーション全体。本文の表示、設定、保存、インポート、エクスポートを行う。 |
| 本文 | ビューア中央に表示する小説のHTML。既定本文または読み込んだ本文を指す。 |
| 既定本文 | 初期状態および初期化後に表示する、アプリ内蔵の説明用本文。 |
| 本文パネル | 本文を囲む背景、余白、角丸、ぼかし、影を持つ表示領域。 |
| 文章 | 本文のうち、「」で囲まれていない地の文章。 |
| 台詞 | 本文のうち、「」で囲まれた台詞。 |
| 設定ドロワー | 表示設定、ファイル操作、初期化を行うサイドパネル。 |
| 目次ドロワー | 本文の見出しから生成した目次を表示するサイドパネル。 |
| 背景メディア | ユーザーが読み込む背景画像または背景動画。 |
| 既定紙画像 | 背景メディアがない場合に表示する、テーマ別の内蔵背景テクスチャ。 |
| 元ファイル | ユーザーが読み込んだテキスト、画像、動画の元データ。個別エクスポートの対象となる。 |
| 実行時データ | 現在の本文、背景メディア、元ファイル情報など、実行中のビューアが使用するデータ。 |
| HTML内蔵データ | HTMLエクスポート時点の本文、設定、背景メディア、元ファイル情報をエクスポートHTML内に保持したデータ。 |
| 書字方向 | 横書きまたは縦書きの本文レイアウト。 |
| 自動配色 | 背景画像の色と明るさから本文色を自動設定する機能。 |

以降は、背景画像と背景動画を総称して「背景メディア」、読み込んだテキスト・画像・動画を「元ファイル」と表記する。

## 画面構成と初期表示

### ビューア画面

- 本文表示領域を画面の中心に配置する。
- 設定ドロワーと目次ドロワーを備える。各ドロワーは同時に開かず、切り替え時には他方を閉じる。
- テーマ切替、設定表示、目次表示の各ボタンを備える。設定ドロワーのテーマボタン系列にはヘルプボタンも配置し、クリックするとキーボードショートカット一覧をモーダルで表示する。モーダルの文字色・背景色は設定ドロワーと同じテーマ変数を共有する。
- ヘルプモーダルの表示中は、背景メディアのドラッグ移動とダブルクリックによる位置リセットを開始しない。
- 読書進捗表示は設定で有効にした場合に画面左下へ表示する。初期状態では非表示。
- インポートやエクスポートなどの失敗は画面上部に通知する。通知は表示から5秒後に自動で閉じ、閉じるアイコンでも閉じられる。

### 初期本文

通常版の起動時は、保存済み本文をサニタイズして表示する。保存済み本文が存在しない場合や空白だけの場合は、Hitohiraの使い方を説明する既定本文を表示する。エクスポートHTMLは、そのHTMLに埋め込まれた本文で起動する。目次生成と読書位置の復元は、起動時に表示する本文が決まった後に行う。

既定テキスト・既定紙画像はビューアに内蔵された初期表示用データであり、ユーザーが読み込んだファイルとは別に扱う。

## 本文表示・文字組み

### 書字方向

- 横書き：上から下へスクロールする。
- 縦書き：`vertical-rl`を使用し、右から左へ進む。横方向にスクロールする。
- 縦書き時、縦方向のホイール入力が優勢な場合は横スクロールへ変換する。
- 書字方向を切り替えるときは、現在の読書位置を可能な範囲で維持する。

### 書体

- 明朝体とゴシック体を切り替えられる。
- 書体設定は本文に適用し、UIはサンセリフ系フォントを使用する。
- 書字方向と書体は、それぞれ2択のセグメントコントロールで選択する。

### 文字組み

| 項目 | 初期値 | 設定範囲 |
|---|---:|---:|
| 文字サイズ | 16px | 10～22px、1px刻み |
| 行間隔 | 2.0 | 1.0～3.0、0.1刻み |
| 文字間隔 | 0.04em | 0～0.08em、0.01刻み |
| 本文幅 | 720px | 480～960px、20px刻み |
| 本文余白 | 48px | 16～80px、4px刻み |
| ルビサイズ | 50% | 30～70%、5%刻み |
| テキスト背景不透明度 | 75% | 0～100%、5%刻み |
| 背景ぼかし強度 | 12px | 0～24px、2px刻み |

本文パネルは最大幅720pxを基準とし、背景色・角丸・余白・ぼかし・影を持つ。書字方向に応じてパネルのレイアウトとスクロール軸を切り替える。

### 段落・ルビ

- 通常段落は先頭を1文字分字下げする。
- 段落先頭が`.dialogue`要素である場合、その段落は字下げしない。
- 文章と台詞の文字色は別々に設定できる。
- HTMLの`ruby`・`rt`要素を表示し、ルビサイズを本文サイズに対する倍率で調整する。
- ルビ文字は選択不可。

### リンク

- マークダウンの単純なリンク記法`[表示文字列](https://example.com)`、`[表示文字列](./AGENTS.md)`、`[表示文字列](docs/SPECIFICATION.md)`と、HTMLの単純な`<a href="https://example.com">表示文字列</a>`を表示する。
- 許可するリンク先は`http://`、`https://`、`./`、`../`、ページ内移動の`#`から始まるURLに限定する。`javascript:`、`data:`、`file:`などのスキームは表示前に除去する。
- `http`/`https`の外部リンクは新しいタブで開き、`rel="noopener noreferrer"`を付与する。ページ内リンクは同一ページ内で移動する。

## テーマ・配色

### テーマ

ライト／ダークの2テーマを備え、テーマ切替ボタンで変更する。

ライトテーマとダークテーマは、画面背景・本文・本文パネル・UIの主要色について、原則として輝度が対称になるように設計する。例外は、可読性・視認性・状態表示を優先する色（アクセント、警告、成功表示、フォーカス表示、画像から算出した自動配色）であり、これらは完全な輝度対称を要求しない。

| 配色項目 | ライト | ダーク |
|---|---|---|
| 画面背景 | `#f7f7f7` | `#0a0a0a` |
| 文章 | `#1c1c1c` | `#e3e3e3` |
| 台詞 | `#595959` | `#b8b8b8` |
| 本文パネル | `#ffffff` | `#000000` |
| 本文パネル不透明度 | 75% | 75% |

テーマ切替時、現在値が切替前テーマの既定色と一致する色項目は切替先テーマの既定色へ更新する。既定色と異なるユーザー指定色は保持する。対象は画面背景・文章・台詞・本文パネルの色である。

### 個別色・自動配色

設定画面で次の色を個別に変更できる。

- 画面背景色
- 文章文字色
- 台詞文字色
- 本文パネル色
- 色の自動選択

自動選択が有効な場合、背景画像の平均色を解析して本文パネル色へ反映し、画像の明るさに応じて文章・台詞の色も調整する。画像解析はテーマ設定そのものを変更しない。背景画像が読み込まれていない場合、または背景が動画・既定紙画像の場合は、色の自動選択を表示したまま無効化し、保存済みの個別色を使用する。背景画像が読み込まれ、寸法を取得できた場合だけ操作を有効化する。画面背景色は画像平均色による自動選択の対象外。

背景画像を切り替えた直後は、新しい画像の寸法を取得するまで個別色を表示する。切り替えや解除の後に旧画像の読み込みが完了しても、その画像の寸法や配色は反映しない。

### 設定ドロワーの配色

ドロワー背景・基本文字色はテーマ用CSS変数を使用し、本文パネル色や本文文字色、自動配色から独立させる。セグメントコントロールはライト／ダークそれぞれにモノクロの対照配色を使用する。

画面スリープ防止を有効にすると、本文表示中はWake Lock APIで画面スリープを防止する。ページ非表示時は解放し、再表示時に再取得する。API非対応・取得失敗時は通常動作を継続し、設定項目「画面スリープを防止」のラベル右隣にステータスを表示する。ステータスは「有効」「待機中」「取得失敗」「利用不可」と定義し、表示時はそれぞれ「（有効）」「（待機中）」「（取得失敗）」「（利用不可）」のように全角丸括弧で囲む。エクスポートHTMLにはこの設定を引き継がない。

## インポート

### 対応形式

| 種類 | 対応形式 |
|---|---|
| テキスト | `.txt`、`.md`、`.markdown` |
| HTML本文 | `.html`、`.htm` |
| 背景画像 | PNG、APNG、JPEG、WebP、GIF、BMP、SVG |
| 背景動画 | ブラウザーが再生可能な動画形式 |

設定ドロワーのファイル選択、またはビューア画面へのドラッグ＆ドロップで読み込む。複数ファイルの選択にも対応する。

### テキストの取り込み

- TXTは安全なHTML本文へ変換して表示する。
- Markdownは安全なHTML本文へ変換し、行頭の`#`〜`######`をそれぞれ`h1`〜`h6`へ変換する。
- Markdown表は、先頭行を`thead`の`th`、区切り行（`---`）以降を`tbody`の`td`として`table`へ変換する。
- 表の直後に箇条書き、番号付きリスト、フェンス付きコードブロックが続く場合は、空行の有無や行内の `|` にかかわらず、別のブロックとして変換する。
- その他の主要なMarkdown記法として、太字、斜体、取り消し線、インラインコード、リンク、引用、箇条書き、番号付きリスト、水平線、フェンス付きコードブロックを安全なHTMLへ変換する。
- HTMLは`#novel-content`要素があればその内容を、なければ`body`の内容を取り込む。
- HTMLに空でない`title`要素がある場合は、その文字列をビューアの表示タイトルとエクスポートHTMLの`title`へ反映する。ファイル名のstemは元ファイル名から取得し、タイトルとは独立して保持する。
- 取り込むHTMLはサニタイズする。
- インポートしたファイル名（拡張子を除く）をHTMLエクスポート時のファイル名の基礎として保持する。
- 新しい本文を取り込んだときは、以前の本文の読書位置を削除して先頭から表示する。
- 元ファイルのBlobと拡張子を保存し、後から元ファイルをエクスポートできるようにする。
  - 複数のテキストファイルは選択順に本文へ結合し、間に水平線を挿入する。元ファイル・ファイル名stem・HTML題名は、最後に正常に読み込めたテキストファイルのものを保持する。
  - 一部のファイルが読み込みに失敗しても、正常に読み込めたファイルの処理を続け、失敗したファイル名と理由を通知する。
  - 本文、設定、読書位置、最後に読み込んだ元テキストファイルを保存し終えるまで画面の本文・題名・元ファイル状態を切り替えない。保存に失敗した場合は保存済みデータを可能な範囲で復元し、既存の画面と元ファイル状態を保って失敗を通知する。

### 背景画像・動画

- 読み込んだ画像または動画を画面背景に設定する。
- 画像と動画は排他的に扱い、最後に読み込んだ一方だけを保持する。
- 画像はBlob URLで表示し、元BlobをIndexedDBへ保存する。画像をBase64化してから表示する方式は使用しない。
- 画像はデコード可能か検証し、寸法を取得できない場合やデコードに失敗した場合は読み込み失敗として扱う。
- MIMEタイプが不明でも、対応する拡張子から画像形式を判定する。
- 動画はミュート・自動再生・ループ・インライン再生で表示する。再生可否はブラウザーが対応する形式・コーデックと自動再生ポリシーに依存する。自動再生が拒否された場合は、背景動画を停止状態で保持し、読み込みごとに一度通知する。エクスポートHTMLの起動時も同じ動作とする。
- 画像・動画の元BlobはIndexedDBへ保存する。新しい背景メディアを読み込むと既存の背景メディアを置き換える。
- 読み込みに失敗した場合は、画面上部に簡潔な理由を通知する。

アプリ独自のファイルサイズ上限は設けない。実際に読み込めるサイズは、ブラウザーのデコード機能、利用可能メモリ、IndexedDB容量、OS・端末の制約に依存する。HTMLエクスポート時にはメディアをHTMLへ埋め込むため、大容量ファイルではメモリ使用量とHTMLファイルサイズが増加する。

IndexedDBの容量超過で元ファイルの保存が中断された場合は、対象ファイル名と保存領域の不足を通知する。そのファイルで表示や個別エクスポートの対象を置き換えず、直前の保存データを維持する。

### 背景メディアの操作

- 背景画像・動画はドラッグまたはタッチ操作で移動できる。
- 移動範囲を制限し、画面内にメディアのない領域が露出しないようにする。
- 背景メディア上をダブルクリックすると表示位置を初期位置へ戻す。
- 動画の位置リセットでは、再生時刻・再生状態・`src`・ロード状態を変更しない。
- ドラッグ中は画面右下にメディア全体の縮小図と表示範囲を示す矩形を表示し、操作が終了または中断されたときに非表示にする。
- ウィンドウサイズ変更時は表示位置と移動可能範囲を再計算する。
- 動画の寸法はメタデータ取得後の`videoWidth`・`videoHeight`に基づいて計算する。

### 既定紙画像

ユーザー背景メディアが存在しない場合は、テーマに対応した内蔵紙テクスチャを表示する。既定紙画像はHTML内のBase64 PNGとして保持し、外部ファイルに依存しない。背景メディアを解除した場合は現在のテーマに対応する既定紙画像へ戻す。既定紙画像はユーザーが読み込んだ画像ファイルとは別のデータであり、個別エクスポート対象ではない。

## エクスポートと元ファイルのエクスポート

### エクスポートUI

- 起動直後は保存済み本文と設定を先に描画し、IndexedDBの元ファイル復元と読書位置のレイアウト待機を初回描画後へ遅延する。遅延復元後に保存内容、背景、エクスポート操作、読書位置を反映する。
- HTMLと個別元ファイルの各ダウンロード行に、生成されるファイルのサイズを表示する。HTMLは書き出し対象と同じ内容を組み立てて計測し、状態変更後にまとめて再計算する。単位は十進のB、KB、MB、GB、TBとし、桁数を抑えて「5 MB」のように表示する。計測中・計測不能時は状態を表示する。
- 開発用`hitohira.html`を編集対象とし、HTML内に圧縮機能を設けない。公開用`public/hitohira.html`は`skills/novel-viewer-build/SKILL.md`のビルド工程で外部開発ツールを使って生成する。HTML/CSS/JavaScriptを構文を保って圧縮し、生成HTMLには圧縮器・辞書・復元処理を埋め込まず、MITライセンス表記を保持する。公開用HTMLから書き出すHTMLも圧縮状態を維持する。製品HTMLは実行時にネットワーク接続を要求しない。
- 公開ビルドの外部ツールは開発時のみ使用し、製品HTMLには同梱しない。各ツールと推移依存のバージョン、著作権表示、ライセンス全文は[第三者ライセンス通知](../THIRD_PARTY_NOTICES.md)に記録する。
- 読み込んだテキスト・画像・動画の個別エクスポートボタンは、対応する実行時Blobが存在する場合に限りDOMへ生成する。
- 不要になったボタンは非表示にせずDOMから削除する。
- `refreshExportButtons()`が実行時Blobの有無と種類を判定し、ボタンDOMを同期する。
- インポート、起動時のデータ復元、初期化など、実行時データが変わる処理の後にボタンを更新する。
- ボタン操作は親コンテナのイベント委譲で処理する。
- 実行時データが存在する個別ファイル項目には、エクスポートアイコンと削除アイコンを並べて表示し、ユーザーが個別にエクスポートまたは削除できるようにする。削除は現在の実行時データと保存データを対象とし、エクスポートHTMLに内蔵されたデータ自体は変更しない。
- HTML・テキスト・画像・動画の名称はクリックできない左寄せラベルとして表示し、右側に操作アイコンを同行配置する。ラベル自体は操作を発生させない。
- 個別ファイル行の操作アイコンは左から削除、エクスポートの順に配置し、エクスポートアイコンを常に行の最右端に揃える。HTML行はエクスポートアイコンのみを最右端に配置する。
- 削除操作後は画面表示も直ちに更新する。テキスト削除時は本文を既定本文・先頭位置へ戻し、背景メディア削除時は既定紙画像へ戻す。
- 保存データの削除・更新に失敗した場合は、操作失敗を通知し、表示と個別エクスポート行を維持する。先に変更した保存値は復元を試み、復元にも失敗した場合は開発者コンソールに記録する。
- 「設定を初期化」ボタンの文字は中央寄せとする。設定変更時には設定オブジェクトの全項目を既定値と比較し、本文・背景メディア・元ファイル情報も含めて初期化で変更される要素が存在するかを判定する。読書位置はHTMLへエクスポートされず、スクロール操作で容易に変更できるため判定対象から除外する。現在の状態が既定状態なら無効、既定状態でなければ有効とする。
- 目次生成のために付与する内部見出しIDなど、表示・本文内容に影響しない実行時属性は本文比較から除外する。
- インポートとエクスポートはドロワー幅いっぱいの同行レイアウトとし、左側にクリックできないラベル、右端に操作用SVGアイコンを配置する。
- 次のUIアイコンは外部画像やフォントを使用せず、SVGとしてHTML内に直接埋め込む：設定、テーマ切替、ヘルプ、目次、閉じる、インポート、エクスポート、削除。
- 埋め込みSVGは`currentColor`でボタン文字色に追従させ、テーマ切替時も個別の画像差し替えを行わない。
- アイコンはシンプルかつミニマルなデザインのピクトグラムとし、装飾的な描画や不要な細部を避ける。線幅・角丸・`currentColor`による配色を統一する。

### 個別ファイルのエクスポート

- 対象はユーザーが読み込んだ元ファイルに限る。既定本文・既定紙画像・設定データは対象外。
- ファイル内容のSHA-256を計算し、64桁の16進値をファイル名のstemとして使用する。
- 元ファイルの拡張子表記を維持する。
- ファイル内容は再エンコードせず、読み込んだ元データのバイト列を維持する。
- SHA-256計算にはWeb Crypto APIの`crypto.subtle.digest('SHA-256', ...)`を使用する。利用できない実行環境ではエクスポートに失敗する。

### HTMLエクスポート

HTMLボタンは、本文・現在の設定・背景画像または動画・必要なエクスポート用データを含む単体HTMLを生成する。公開用ミニファイHTMLからのエクスポートは圧縮済みのHTML/CSS/JavaScriptを維持し、MITライセンス表記も保持する。

- 本文はサニタイズして埋め込む。
- 現在の設定を初期設定JSONへ反映する。
- 背景メディアは元データをData URLとしてHTMLへ埋め込む。画像は再エンコードせず元データを使用する。
- エクスポートHTMLには実行時の `blob:` URL や背景表示用のクラスを残さない。背景画像・動画は埋め込みData URLから起動時に復元する。
- 動画は元データを埋め込み、ミュート・自動再生・ループで再現する。ブラウザー標準機能による再エンコードは行わない。
- テキスト元ファイルはBase64と拡張子・MIME情報を埋め込む。背景メディアの元ファイル情報は埋め込みメディアを再利用し、メディア本体を重複して埋め込まない。
- 起動時はHTML内の埋め込みデータから背景メディアと個別エクスポート用データを復元し、画面へ反映する。
- 読書位置と背景メディアの表示位置はHTMLへ埋め込まない。
- エクスポートHTMLは通常版と同じビューア機能を持つ。
- エクスポートHTMLのファイル名stemは読み込んだテキストのファイル名stemとし、未設定の場合は`Hitohira`とする。HTMLの`title`には読み込んだHTMLの空でない題名を優先し、なければファイル名stemを使う。したがってHTMLの題名とダウンロードファイル名stemは異なる場合がある。
- エクスポート時に設定ドロワーを閉じる。
- HTMLまたは元ファイルのエクスポート処理が失敗した場合は、不完全なファイルを出力せず、操作名と再試行の案内を画面上部に通知する。例外の詳細はブラウザーの開発者コンソールに記録する。
- エクスポート本文は、元テキストファイルの有無にかかわらず、その時点で画面に表示されている本文のサニタイズ済みHTMLを保存する。元テキストBlobが存在する場合だけ、個別エクスポート用のBase64データを保存する。
- 背景メディアが存在しない場合は`mediaDataUrl`を保存せず、起動時はテーマ対応の既定紙画像を表示する。画像・動画のどちらか一方だけを保存し、`mediaType`とData URLの種類を一致させる。
- エクスポートHTML内の埋め込みデータは変更不可のスナップショットであり、エクスポートHTML上での削除操作は現在の実行時データだけを削除する。

## エクスポートHTML内のデータと初期化

### データの区分

- **実行時データ：** 現在の本文、背景メディア、個別エクスポート用Blobなど、ビューアが現在使用しているデータ。
- **HTML内蔵データ：** HTMLエクスポート時点の本文、背景メディア、元ファイル情報、設定。
- **既定データ：** ビューアに最初から内蔵されている既定本文・既定紙画像・既定設定。

この3種類を混同しない。HTML内蔵データは、エクスポートHTMLを再読み込みしたときの復元元となる。既定データは初期化後の表示に使用する。

### 通常版の初期化

「設定を初期化」を実行すると、設定・本文・読書位置を既定状態へ戻し、背景メディアを解除してテーマに対応した既定紙画像を表示する。通常版ではLocalStorageのユーザー設定・本文・読書位置、およびIndexedDBのインポート元テキスト・背景メディアを削除する。テキスト・画像・動画の個別エクスポート用Blob情報を破棄し、対応ボタンをDOMから削除する。HTMLボタンは残す。
設定・本文・背景メディア・元ファイルのいずれかに既定状態との差分がある場合に「設定を初期化」を有効にする。読書位置だけの変更では有効にしない。背景メディアと本文元ファイルは一つのIndexedDBトランザクションで削除する。保存処理が失敗した場合は画面を初期化せず、失敗を通知する。

### エクスポートHTMLの初期化と再読み込み

- エクスポートHTMLには、初期化用の既定設定・既定本文と、エクスポート時点のユーザー本文・背景メディア・設定を別々に保持する。
- エクスポートHTMLで初期化すると、実行時データを破棄して既定設定・既定本文・既定紙画像へ戻す。個別エクスポート用Blob情報とテキスト・画像・動画のボタンを削除する。
- 初期化してもHTML内蔵データ自体は削除・書き換えない。
- 初期化後にエクスポートHTMLを再読み込みすると、HTML内蔵データから実行時データを再構築し、対応する個別エクスポートボタンを再生成する。
- 内蔵JSONの読み取り、背景データの復号、またはブラウザーによる画像・動画の読み込みに失敗した場合は、画面上部に復元失敗を通知し、HTML本文と既定紙画像を表示する。読み込めなかった背景の個別エクスポートボタンは表示せず、復元済みの本文元ファイルは引き続き個別エクスポートできる。自動再生の拒否時は背景動画を停止状態で保持する。
- したがって、初期化直後はHTML以外の個別エクスポートボタンがなく、同じHTMLを再読み込みすると、HTML内蔵データが存在する種類のボタンが復元される。

## 目次・読書進捗・読書位置

### 目次

- 本文内の`h1`～`h6`を収集し、見出し階層に応じたインデントで目次を生成する。
- 目次項目を選択すると対応する見出しへ移動し、目次ドロワーを閉じる。
- 現在位置に対応する見出しを判定し、目次上で強調する。
- 見出しがない場合は、その旨を表示する。

### 読書進捗

- スクロール位置とスクロール可能範囲から0～100%を算出する。
- 横書きでは縦スクロール、縦書きでは横スクロールを使用する。
- スクロール可能範囲がない場合は0%とする。
- 進捗表示は設定で表示・非表示を切り替えられる。初期値は非表示。

### 読書位置の保存

読書位置は文書ID付きのLocalStorageキーへ保存する。保存内容は進捗率、スクロール位置、書字方向、本文位置の復元に必要な見出し・ブロック情報、背景メディアの移動量とする。スクロール、キーボード操作、背景メディア移動、ページ離脱時に更新する。復元中は保存せず、保存できない場合は現在の表示を継続する。

### 実行時メディアの保存

背景メディアと読み込んだテキストの元ファイルは、IndexedDBデータベース`hitohira_media_db`（バージョン1）に保存する。オブジェクトストア名は`background_media`とし、背景メディアはキー`current`、テキスト元ファイルはキー`current_text`で管理する。読書位置・設定・本文のLocalStorage保存とは独立して扱う。

### 読書位置の復元

- 本文のレイアウト確定後に保存値を復元する。
- 保存時と書字方向が同じならスクロール位置を使用し、異なる場合は本文位置、進捗率の順に復元する。
- 閲覧中に書字方向を切り替えるときは、変更直前の本文位置を取得し、切り替え後のレイアウトで同じ本文ブロックへ移動する。対象ブロックがない場合は進捗率を使用する。
- 新しい本文を読み込んだ場合は先頭から開始する。
- 読書位置はエクスポートHTMLへ埋め込まず、開いたブラウザーの保存領域だけで復元する。

## ページ送り・テキスト選択・カーソル

### ページ送り

本文領域のクリック位置に応じ、書字方向に沿って画面のおよそ75%相当を移動する。
横書きでは`ArrowUp`／`ArrowDown`、縦書きでは`ArrowLeft`／`ArrowRight`で書字方向に沿ってスクロールする。横書きでは`PageDown`／`Space`を本文の進行方向、`PageUp`／`Shift+Space`を逆方向へ移動する。縦書きでは`PageDown`／`Space`を横スクロールの負方向（左）、`PageUp`／`Shift+Space`を正方向（右）へ移動する。キー押下直後の最初の移動はsmoothで行い、アニメーション完了後も押下を継続している間は一定速度で移動する。`keyup`またはウィンドウ離脱でsmooth移動と継続移動の両方を停止する。`Home`／`End`は本文の先頭／末尾へ移動する。`F1`でキーボードショートカットのヘルプを表示する。`F11`でフルスクリーンを切り替え、同じキーを再度押すと元の表示へ戻す。`S`で設定、`O`で目次を開く。入力欄・ボタンなどの操作中はショートカットを適用しない。
単一クリックによるページ送りは短時間保留し、本文上のダブルクリックが発生した場合はキャンセルする。ダブルクリック時はページ送り・選択解除などの特別な処理を行わず、単語選択をブラウザーの標準動作に任せる。

### テキスト選択との競合防止

- 既にテキスト選択範囲がある場合、最初のクリックは選択解除操作として扱い、ページ送りしない。
- ポインター操作がキャンセルされた場合は操作状態を解除する。

### カーソル

本文上でテキスト行の矩形内にポインターがある場合はテキスト選択カーソルを表示する。文字の描画ピクセル単位ではなく行矩形で判定するため、行内の文字間空白も対象となる。行間や本文背景では標準カーソルを表示する。

## 保存データとストレージ

### LocalStorage

| キー | 内容 |
|---|---|
| `hitohira_settings` | 表示設定・配色・ファイル名等 |
| `hitohira_content` | 読み込んだ本文HTML |
| `hitohira_position:<documentId>` | 文書単位の読書位置・進捗率・背景メディア移動量 |

設定・本文・読書位置は用途ごとに別キーへ保存する。

### IndexedDB

- データベース名：`hitohira_media_db`
- オブジェクトストア名：`background_media`
- 背景メディアのキー：`current`
- インポート元テキストのキー：`current_text`

背景画像・動画はBlobとして`current`へ保存し、両者は同じレコードを共有する。テキスト元ファイルはBlobと拡張子を`current_text`へ保存する。LocalStorageには画像・動画・元テキストファイルの本体を保存しない。

### 保存範囲と制約

LocalStorage・IndexedDBの内容はブラウザーおよび保存領域ごとに独立し、別ブラウザー・別オリジンへ自動同期されない。ユーザーによるデータ消去、プライベートモード、容量制限、ブラウザーのストレージポリシーなどにより保存データが失われる場合がある。

## テスト実行

- オフライン配布検証はChromeまたはEdgeの一時プロファイルと動的CDPポートを使用し、公開HTMLを開く前にブラウザーネットワークを遮断する。本文表示・設定・本文ファイルの読込・保存・再読み込み後の復元・HTMLエクスポートを実行し、外部接続が失敗すること、アプリ操作中にHTTP(S)通信が発生しないこと、エクスポートHTMLが外部リソースと実行元Blob URLに依存しないことを確認する。
- Node.js標準モジュールでビューアの処理を実行する単体テストは`node tests/run_tests.js unit`で実行し、実行時間の目安は0秒（10秒単位に丸めた値。実測は1秒未満）とする。
- ブラウザー操作テストは `node tests/run_tests.js browser` で実行する。比較時はPowerShellで `$env:NOVEL_VIEWER_BROWSER = 'chrome'` または `$env:NOVEL_VIEWER_BROWSER = 'edge'` を設定する。指定しない場合はインストール済みのChromeを優先し、見つからない場合はEdgeを選ぶ。
- Firefoxの基本操作テストは `pwsh -File tests/run_tests.ps1 -Suite firefox` または `node tests/run_tests.js firefox` で実行する。標準のインストール先以外のFirefoxを使う場合は `NOVEL_VIEWER_FIREFOX_PATH` に実行ファイルのパスを設定する。WebDriver BiDiを動的ポートで起動し、単体HTMLの表示と実キーによる設定ドロワーの開閉を確認する。Firefoxは明示指定したときに実行する。
- ポリシーと容量を制御する追加ケースは、PowerShellで `$env:NOVEL_VIEWER_POLICY_TESTS = '1'` を設定して同じコマンドを実行する。テストはループバック接続が可能な環境で実行する。一時HTTPサーバーがページ単位の `Permissions-Policy` を設定し、CDPがそのオリジンの容量を一時的に上書きする。テスト終了時に容量の上書きを解除し、サーバーと一時プロファイルを片付ける。
- 容量制御付きテストでは上限を8 MiBに設定し、本文・画像・動画の入力サイズ、オリジン使用量の差、取り込みとHTML書き出しの所要時間、出力サイズをログに記録する。所要時間には操作と完了確認が含まれる。使用量の差はレコードの置き換えも含む。これらの計測値はアプリの容量制限やタイムアウトには使用しない。
- 全テストは`node tests/run_tests.js all`で実行する。
- 開発者向けに`pwsh -File tests/run_tests.ps1 -Suite unit|browser|all`でも各JavaScriptテストを直接実行できる。`-Suite`省略時は全テストを実行する。
- ブラウザー操作テストはテスト側でChromeまたはEdgeを起動し、CDP接続と終了処理まで行う。既定では動的ポートを使用する。ループバックTCPを使えない場合は、PowerShellで `$env:NOVEL_VIEWER_CDP_PIPE = '1'` を設定してから `pwsh -File tests/run_tests.ps1 -Suite browser` を実行すると、起動したブラウザーとのパイプで接続する。サンドボックス無効化が必要な隔離環境だけ`pwsh -File tests/run_tests.ps1 -Suite browser -DisableSandbox`を明示指定する。通常実行ではサンドボックスを無効化しない。
- ブラウザー操作テストは既定でヘッドレス起動するため、目視できるブラウザーウィンドウは表示しない。Chrome固有の起動・CDP挙動を目視調査する場合は`pwsh -File tests/run_tests.ps1 -Suite browser -ShowBrowser`を指定し、必要に応じて`-DisableSandbox`を併用する。
- テスト結果はGoogle Test形式の`[==========]`、`[  PASSED  ]`、`[  FAILED  ]`で実行件数と成功・失敗件数を表示する。全単位の実行が成功した場合はブートストラップが`✓ テスト実行成功`を表示する。失敗・例外発生時は終了コード、エラーメッセージ、スタックトレースを記録し、原因を追跡可能な形式で報告する。未実施の場合も理由と終了コードを表示する。
- テストケースはGoogle Test形式を参考に`[ RUN ]`、`[ OK ]`、`[ FAILED ]`、`[==========]`、`[ PASSED ]`で報告し、スイート名・ケース名の階層を表示する。
- テストコードは文芸的プログラミングで実装し、仕様の章立てに沿ったスイート、前提・操作・期待結果が読めるテスト名、意図を補足するコメントと共通ユーティリティを用いる。
- テスト実行後は成否に関わらず、起動プロセス、CDP接続、一時ファイル、ブラウザープロファイル、ダウンロード領域、テスト用保存データをクリーンアップし、環境に副作用を残さない。
- Windowsでブラウザー操作テストを終了するときは、起動したブラウザーPIDのプロセスツリー（子プロセスを含む）を終了してからプロファイルを削除する。ユーザーが起動した別のブラウザーPIDは対象にしない。
- ブラウザー操作テストはブラウザーとCDPを自動起動し、動的ポートを優先する。手動起動や固定ポートを前提にせず、CDP接続失敗時は起動引数、ポート、対象URL、終了コード、標準エラーを報告する。
- TCP接続の動的ポート取得では、起動直後にポートを確認し、未生成なら`DevToolsActivePort`の生成通知（ファイル監視）を待つ。通知前にブラウザーが終了した場合は終了コード・シグナルを報告する。パイプ接続では対象ページの取得と接続をCDPコマンドで行う。
- ブラウザー操作テストを変更・追加した場合は、変更後の同テストを必ず実行する。全件成功または未実施理由・終了コードを記録してから変更を完了とする。
- 中断時もプロセスツリーと一時資源を後始末し、ユーザーが起動したブラウザーを停止しない。
- テスト結果の角括弧付き状態ラベルはGoogle Testに準拠し、`[ RUN      ]`、`[       OK ]`、`[  FAILED  ]`、`[  RESULT  ]`、`[==========]`、`[  PASSED  ]`を使用する。独自の`ALL`付きラベルは追加しない。
- PowerShell実行時はNode.jsのUTF-8標準出力とコンソール出力エンコーディングを統一し、終了時に呼び出し元設定へ復元する。
- PowerShellのテストラッパーはNode.jsのUTF-8出力をUTF-8として受信・表示し、終了時に`OutputEncoding`とコンソール出力エンコーディングを元へ戻す。
