# 設計決定記録

製品構成やデータの扱いなど、後続作業へ影響する設計判断とその理由を記録する。ここでは「なぜその構成を選んだか」を扱い、利用者から見た現在の動作は[仕様書](./SPECIFICATION.md)、確認済みの経験則は[開発知見](./DEVELOPMENT_KNOWLEDGE.md)、未確定の論点は[課題表](./ISSUES.md)を正とする。

以下は過去の合意・実装方針を現在の資料と作業履歴から整理して記録したもの。実際の決定日を確認できないため、日付はこの資料への記録日を示す。

## 記録項目

| 列 | 記録する内容 |
|---|---|
| ID | 設計決定を一意に参照する識別子。[共通採番規則](./IDENTIFIERS.md)に従い、`ADR-001`から順に付与し、廃止後も再利用しない。 |
| 記録日 | この記録へ反映した日。元の決定日と異なる場合はその旨を本文へ記す。 |
| 状態 | 現在有効な判断は「採用」、置き換えられた判断は「廃止」とする。 |
| 決定 | 採用・廃止した方針を短く記す。 |
| 背景・論点 | 判断が必要になった理由と、主要な選択肢。 |
| 判断理由 | 選択した理由と優先した価値。 |
| 影響・制約 | 実装・運用・利用者に生じる結果、守るべき制約。 |
| 再検討条件 | 判断を見直す条件。該当しない場合は「特になし」。 |
| 関連資料 | 仕様・実装・ビルド・検証資料へのリンク。 |
